# SOLE STORE — فروشگاه آنلاین کفش (NestJS + Next.js + MongoDB)

```
apps/api   → بک‌اند NestJS  (http://localhost:4000/api)
apps/web   → فرانت‌اند Next.js، فارسی/انگلیسی (http://localhost:3000)
```

## امکانات
**فروشگاه:** صفحه‌ی اصلی، لیست محصولات با فیلتر (برند، دسته، جنسیت، سایز، رنگ، قیمت، تخفیف، موجودی)، جستجو و مرتب‌سازی، صفحه‌ی محصول با انتخاب سایز/رنگ،
نظرات و امتیاز (فقط خریداران، با تأیید ادمین)، علاقه‌مندی‌ها، سبد خرید (مهمان + ادغام بعد از ورود)، کد تخفیف، محاسبه‌ی هزینه‌ی ارسال بر اساس استان و وزن،
ثبت سفارش و پرداخت با زرین‌پال، پیگیری سفارش، فاکتور قابل چاپ/PDF، ایمیل و پیامک اطلاع‌رسانی، دوزبانه (فارسی RTL / انگلیسی)، SEO (متادیتا + JSON-LD).
**حساب کاربری:** ورود/ثبت‌نام با OTP موبایل (sms.ir) یا ایمیل و رمز، تأیید ایمیل، فراموشی/تغییر رمز، آدرس‌ها، خروج از همه‌ی دستگاه‌ها.
**پنل ادمین (`/admin`):** (خبرنامه هم اضافه شد) داشبورد فروش، محصولات (تنوع سایز×رنگ، موجودی، آپلود تصویر)، برند و دسته، سفارش‌ها و تغییر وضعیت و کد رهگیری، نظرات، کد تخفیف،
قوانین ارسال، کاربران و نقش‌ها (Admin / Content / Support)، پرداخت‌ها، گزارش فعالیت (Audit log).

## طراحی و ظاهر (ریدیزاین مرحله‌ی ۵ تا ۹)
- **دو تم کاملاً متفاوت:** *Light Luxury* (کاغذی گرم، مرکب و برنزی؛ گوشه‌های تیز، تخت، فونت سریف) و *Dark Premium* (مشکی عمیق، لیمویی نئونی و نارنجی؛ گوشه‌های نرم، سایه‌ی درخشان، فونت Grotesk). فقط رنگ عوض نمی‌شود: شعاع گوشه‌ها، سایه‌ها، فونت عنوان و کنتراست هم در هر تم فرق دارد.
- همه‌ی مقدارها **CSS Variables** هستند (`src/app/globals.css`) و به Tailwind وصل شده‌اند (`tailwind.config.ts`). تغییر هویت بصری = تغییر همین چند متغیر.
- تغییر تم با دکمه‌ی هدر؛ انتخاب کاربر ذخیره می‌شود، پیش‌فرض از تنظیم سیستم‌عامل خوانده می‌شود، و با `next-themes` **بدون فلش** هنگام بارگذاری اعمال می‌شود. تعویض تم با افکت دایره‌ای (View Transitions) انجام می‌شود و در مرورگرهای بدون پشتیبانی بی‌صدا آنی عوض می‌شود.
- فارسی/انگلیسی (RTL/LTR) با خصوصیات منطقی CSS؛ هیچ‌جا حرف‌های فارسی جدا از هم انیمیت نمی‌شوند.
- **انیمیشن:** Framer Motion (نسخه‌ی سبک `LazyMotion`)؛ فقط `transform` و `opacity`؛ احترام به `prefers-reduced-motion`؛ پارالاکس فقط روی صفحه‌های بزرگ؛ Skeleton برای لیست و صفحه‌ی محصول.
- هیرو فعلاً یک **تصویر برداری (SVG)** از کفش است، چون عکس واقعی در دسترس نبود. برای عکس حرفه‌ای: فایل را در `apps/web/public` بگذار و `NEXT_PUBLIC_HERO_IMAGE=/hero.webp` را در `.env.local` تنظیم کن.
- متن بخش «مزیت‌ها» (اصالت کالا، ارسال، پرداخت امن، پشتیبانی) عمومی است؛ قبل از انتشار صحتش را با کارفرما تأیید و در `src/messages/*.json` (کلیدهای `home.benefit_*`) ویرایش کن.
- پنل ادمین چیدمان مستقل دارد (سایدبار + نوار بالا، بدون هدر/فوتر فروشگاه) ولی از همان تم‌ها استفاده می‌کند.
- وابستگی‌های جدید فرانت: `framer-motion`, `next-themes` (پس از به‌روزرسانی حتماً `pnpm install` بزن).

## پیش‌نیازها
Node.js 20 یا 22 · pnpm (`npm i -g pnpm`) · MongoDB Community (به‌صورت Replica Set) · mongosh

## ۱) MongoDB محلی روی ویندوز (Replica Set)
تراکنش‌ها (کم کردن موجودی و ثبت سفارش) فقط روی replica set کار می‌کنن.

**اگر MongoDB را به‌صورت Service نصب کرده‌ای:** فایل `mongod.cfg` (مثلاً `C:\Program Files\MongoDB\Server\<نسخه>\bin\mongod.cfg`) را با Notepad در حالت Administrator باز کن و اضافه کن:
```yaml
replication:
  replSetName: rs0
```
سپس سرویس **MongoDB Server** را Restart کن. **یا** اجرای دستی: `mkdir C:\data\rs0` و `mongod --replSet rs0 --dbpath C:\data\rs0 --bind_ip 127.0.0.1`

فقط یک بار: `mongosh --host 127.0.0.1` و
```
rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "127.0.0.1:27017" }] })
```

## ۲) بک‌اند
```
pnpm install
cd apps/api
copy .env.example .env
```
در `.env` مقدارهای `JWT_ACCESS_SECRET` و `OTP_HMAC_SECRET` را با دو رشته‌ی تصادفی جدا عوض کن (تا عوض نشوند برنامه بالا نمی‌آید):
`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

**اگر از مرحله‌ی قبل `.env` داری:** این متغیرهای جدید را از `.env.example` به آن اضافه کن:
`FRONTEND_URL`, `UPLOAD_DIR`, `SMSIR_ORDER_TEMPLATE_ID`, `ZARINPAL_MERCHANT_ID`, `ZARINPAL_SANDBOX`, `SMTP_*`.

```
pnpm start:dev        # از داخل apps/api
pnpm seed:admin       # ساخت ادمین با ADMIN_PHONE (با OTP وارد می‌شوی؛ در حالت console کد در ترمینال چاپ می‌شود)
pnpm seed:demo        # (اختیاری) برند، دسته و ۱۰ محصول نمونه
```

## ۳) فرانت‌اند
```
cd apps/web
copy .env.example .env.local
pnpm dev
```
مرورگر را روی http://localhost:3000 باز کن. فرانت درخواست‌های `/api` و `/uploads` را به NestJS پروکسی می‌کند، پس CORS و مشکل کوکی ندارد.

## ۴) تست سریع کل مسیر
1. `pnpm seed:admin` ← در `/login` با شماره‌ی ادمین وارد شو (کد OTP را از ترمینال بک‌اند بردار) ← به `/admin` می‌روی.
2. اگر `seed:demo` را نزده‌ای: برند و دسته بساز، سپس محصول جدید با تنوع‌ها و تصویر بساز.
3. در یک پنجره‌ی ناشناس با شماره‌ی دیگر وارد شو، به سبد اضافه کن، آدرس بساز و پرداخت کن (Sandbox زرینپال).
4. در پنل ادمین سفارش را به «در حال آماده‌سازی» و «ارسال‌شده» (با کد رهگیری) ببر.

## امنیت پیاده‌شده
argon2id، OTP با HMAC و یک‌بارمصرف و محدودیت ارسال/تلاش، قفل حساب، Refresh Token چرخشی با تشخیص استفاده‌ی مجدد (کوکی httpOnly + SameSite=Strict)،
ابطال فوری توکن‌ها، احراز هویت پیش‌فرضِ همه‌ی مسیرها، RBAC سمت سرور، جلوگیری از IDOR، محاسبه‌ی تمام قیمت‌ها/تخفیف/ارسال فقط در سرور،
رزرو موجودی با تراکنش (بدون فروش بیش از موجودی)، تأیید پرداخت server-to-server و idempotent، آپلود با بررسی magic bytes و بازکدگذاری تصویر،
Rate limit، Helmet، CORS محدود، Validation سخت‌گیرانه (whitelist)، پاک‌سازی ورودی در برابر NoSQL injection و prototype pollution،
پاسخ یکسان برای جلوگیری از user enumeration، Audit log عملیات کارکنان، هدرهای امنیتی در Next.js، escape در JSON-LD.

## چک‌لیست قبل از تحویل نهایی / انتشار (مهم)
- **اولین build را حتماً خودت بزن** (`pnpm --filter api build` و `pnpm --filter web build`). این کد در محیطی نوشته شد که اینترنت نداشت؛ فقط syntax بررسی شده، نه type-check و اجرا.
- فرمت درخواست‌های **زرین‌پال** و **sms.ir** را یک بار با مستندات رسمی‌شان تطبیق بده و با مرچنت واقعی (`ZARINPAL_SANDBOX=false`) تست کن.
- HTTPS اجباری، `NODE_ENV=production`، `TRUST_PROXY=true` پشت reverse proxy، و secretهای واقعی.
- Content-Security-Policy سخت‌گیرانه (با nonce) را در Next.js اضافه کن.
- فایل‌های `uploads/` و دیتابیس را پشتیبان‌گیری کن (یا از S3/MinIO استفاده کن).
- `SMTP_*` را برای ایمیل واقعی تنظیم کن. حساب ادمین را با رمز قوی بساز.
- سفارش‌هایی که پرداخت‌شان تأیید شده ولی سفارش لغو/منقضی شده، در «پرداخت‌ها» با وضعیت «نیازمند بازپرداخت» دیده می‌شوند.
